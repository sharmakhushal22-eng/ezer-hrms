## Data access (same backend as the website)
- `import { api, ApiError, appendFile, type PickedFile } from '@/core/api'` — calls the website's `/api/*` with the ESS bearer token. `api<T>(path, { method, body, form, query, employeeId })`. Pass `employeeId` when the website's call appends `?employee_id=` (lib/ess/api.ts does for most `/api/ess/*`). Errors throw `ApiError` (`.message` = server's `error` string, `.status`, `.body`).
- `import { supabase, must } from '@/core/supabase'` — public anon client, ONLY for the queries the website itself runs directly against Supabase (copy them verbatim, same table/columns/filters, scoped to the signed-in employee). Never broaden a query.
- `import { useEmployeeId, useSession } from '@/core/session'`; `import { useEmployee } from '@/core/employee'` (the full EmployeeDetail record the web portal loads: id, emp_code, full_name, first_name, designation, company_id, l1_manager_id, dept_name, company_name, location_name, profile_photo, …); `import { useMenu, canRaiseMrf } from '@/core/menu'` (/api/ess/menu: is_rm, is_hod, can.approvals/company/reports, approval_types, roles, modules, super_admin).
- Queries: `useQuery({ queryKey: ['<module>', ...], queryFn })`. Key prefix = your module name. After a mutation: `invalidate('<prefix>', ...)` from `@/core/query` for every affected key (incl. `'today'` for Home figures, `'notifications'`). Screens: pass `onRefresh={() => q.refetch()}` (or a Promise.all of refetches) to `Screen`/`TabScreen` for pull-to-refresh. AppState foreground refetch is global already.
- Links the website stores (e.g. 'tab:leave', '/ess?tab=approvals'): `import { openLink, routeForView } from '@/core/links'`.
- Pure website logic: import directly via `@web/<path under lib>` (e.g. `import { fmtDate } from '@web/today/format'`) ONLY if the module and everything it imports is dependency-free (no supabase, next, react-dom, server-only, node crypto, window/document/localStorage at module top level). `.ts` extension imports inside lib work in Metro. If a module isn't safe, copy the needed pure function into your feature with a comment naming the source file.
- Dates: website stores 'YYYY-MM-DD'; use `ymd`, `parseYmd`, `fmtDay` from `@/ui/overlays`. Times displayed in en-IN like the web.

## UI kit (use it; do not hardcode hex colours — use the palette)
- `import { useTheme } from '@/ui/ThemeProvider'` → `const { C, isDark } = useTheme()`. Palette keys mirror the website's `C`: ink, inkSoft, muted, faint, brand, brandDeep, brandTint, brandEdge, onAccent, surface, canvas, sunken, line, lineStrong, positive/warning/critical/info + …Tint + …Edge, chip, chipInk, hair, gradFrom, gradTo, dark, onDark, scrim. Exceptional literal colours that the website itself hardcodes (e.g. calendar day-code colours, gold #D4A017) may be copied as named constants with a source comment.
- `import { F, W, S, R, FONT, toneOf, elevation, type Tone } from '@/ui/theme'` — F: micro 11, tiny 12, small 13, body 14, lead 15, title 18, page 22, display 28. S: xs4 sm8 md12 lg16 xl24 xxl32. R: sm7 md10 lg14 card18 xl20 pill.

- `@/ui/overlays`: `Sheet({visible,onClose,title,footer,full})` (bottom sheet), `SelectSheet({visible,onClose,title,options:[{value,label,note,disabled}],value,onPick,searchable})`, `DateSheet({visible,onClose,value,onPick,min,max,title})`, `useOverlay()` → `{ notify(msg,'success'|'error'|'info'), confirm({title,message,confirm,cancel,destructive}) → Promise<boolean>, prompt({title,message,input:{placeholder,required}}) → Promise<string|null> }`. - Gradients: `expo-linear-gradient`. Images: `expo-image`. Charts/rings/donuts: `react-native-svg`.
- Files: pick with `expo-image-picker` / `expo-document-picker` → build a `PickedFile {uri,name,type,size}` → `await appendFile(form, 'file', f)` → `api(path, { method:'POST', form })`. Open/download: `expo-web-browser` `openBrowserAsync(url)` for signed URLs / PDFs, or `expo-file-system` (`File.downloadFileAsync`) + `expo-sharing` `shareAsync` when the user must save a file. Location: `expo-location` (request foreground permission first, explain refusal).
- Rule from the website: define sub-components at MODULE level, never inside another component (prevents remount/focus loss). Keep each file < ~600 lines; split by screen/section.
- Loading / empty / error states on every screen (use the website's copy). Keyboard: forms inside `Screen` already avoid the keyboard; put long forms' submit button in `Screen footer`.
