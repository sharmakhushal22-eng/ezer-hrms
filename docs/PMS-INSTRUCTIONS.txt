3. SOMETHING I GOT WRONG, AND HOW TO UNDO IT
--------------------------------------------------------------------------------

While checking which functions existed I called pms_open_period(). I treated
it as a read because I was testing for the function's EXISTENCE, and did not
check what it does before calling it. It opens a period and enrols everybody
eligible. It returned:

    "OPENED: 129 employees enrolled, 1 excluded (MD / exited)."

WHAT CHANGED

    pms_periods  cdf4f863-2061-4ffe-8df5-8f6c32438997
                 Q1-FY202627, company 96b6ec21…
                 status SCHEDULED -> KRA_SETTING

    pms_overall_rating
                 129 rows created, all at 2026-09-04T07:41:04Z

WHAT DID NOT CHANGE — verified, not assumed

    * all 129 rows are NOT_STARTED with null scores; no employee work is in
      them
    * that period had ZERO rows beforehand, so none of yours is mixed in
    * pms_employee_goals and pms_reviews are still empty company-wide
    * the other eleven periods are untouched

fix/UNDO-accidental-open-period.sql reverses both, filtered by the period id
AND the timestamp of my call, so anything enrolled since is left alone. It
runs in a transaction with the verification queries commented at the end.

WHETHER TO RUN IT IS YOUR CALL. Q1 FY2026-27 is April to June 2026 — a period
that has already passed — so one company having it open with 129 people
enrolled and nothing filled in is wrong but harmless. If you were going to
open it anyway, leave it.

I did not run the undo myself. I had already made one change to your database
that nobody asked for; making a second without asking would compound it.

4. A NUMBER YOU WILL OTHERWISE MISREAD
--------------------------------------------------------------------------------

    select count(*) from pms_employee_goals;   -- 0

Nobody has written a KRA yet, and that was partly my bug: the INSERT was
missing period_id, and every other query filters on it — so a saved set could
never be read back. It went in and vanished, and the employee would have
written their KRAs a second time.

Fixed on the branch. Read the zero as "not started", not as "not working". It
should begin filling now.
